# 公開チャットプロンプト管理 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use subagent-driven-development to implement this plan task-by-task.

**Goal:** adminから公開チャット3種のプロンプトを編集・保存・比較・公開・復旧する。
**Architecture:** Supabaseの追記型版テーブルと公開版参照を正本にする。共通のテンプレート定義・検証・repositoryをpackages/sharedに置き、webとadminで使用する。DB取得失敗時には現行文面へ退避する。
**Tech Stack:** Next.js、TypeScript、Supabase/PostgreSQL、Vitest。
**Spec:** https://github.com/codeforjapan/saga-broadlistening/issues/135

## Global Constraints

- `top-chat-system`、`bill-chat-system-normal`、`bill-chat-system-hard`のみ実装する。
- 初期生成文面は現行と一致。参照資料が空のときはセクションを省略する。
- 保存済み版は上書きしない。公開は明示操作。復旧は過去版を公開し直す。
- 全admin境界でrequireAdmin。RLS有効・ポリシーなし。RPCはservice_role限定。
- Langfuse追加連携とインタビューの実行経路変更は対象外。
- UIは日本語。Buttonとデザイントークン、routes関数を使う。
- 共通コードはpackages。純粋関数に単体テスト、DB関数に実DB統合テスト。
- 実装者は担当ファイルのみ変更し、commit/pushをしない。最終セルフレビュー後にコントローラーがまとめてcommitする。

## 運用手順

1. DB migration を先に適用し、`ai_prompts`、`ai_prompt_versions` と保存・公開 RPC が使える状態にする。その後に web と admin をデプロイする。
2. admin の「公開チャット設定」から「公開チャットのプロンプトを編集する」を開く。設定画面のモデルや Web 検索の設定は、この版管理とは別に保持する。
3. 対象を選び、本文と理由を入力して「下書きを保存」を押す。保存だけでは公開チャットへ反映されない。初期状態の3件には DB の本文・版がなく、最初の明示的な保存と公開まで web はコードの初期文面を使う。画面表示や読み込みでは DB を書き換えない。
4. 保存履歴から対象版を編集欄に読み込み、公開中の本文との差分とプレビューを確認する。公開理由を入力して公開する。過去版へ戻す場合も履歴からその版を選び、理由を入力して公開する。公開時に過去版の本文を変更せず、公開先の参照を切り替える。
5. 版と公開操作の履歴は保持する。別の管理者による更新で競合した場合、「最新状態を取得（入力を保持）」を押し、編集中の本文を残したまま最新版と差分を確認する。

プレビューは編集中の本文に公開済み施策データを差し込む。LLM を呼ばない。トップの一覧は通常難易度の施策情報を使い、施策チャットのプレビューは選択した施策とプロンプトの難易度に対応する内容を使う。公開済みで AI 質問が有効な施策だけ参照資料を含める。

この変更では会話開始時の版固定を行わない。公開の切り替えは次のチャット送信から効く。AI インタビューへの展開では、版テーブル・保存公開 RPC・履歴の考え方は流用できる。一方、インタビュー用の固定文面と組み立て処理・出力契約を分離し、セッション単位のプロンプト snapshot と設定履歴を追加してから実行経路を変更する必要がある。現在のインタビュー実行経路は変更しない。
