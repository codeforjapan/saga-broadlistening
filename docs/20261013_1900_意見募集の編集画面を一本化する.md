# 意見募集の作成・編集画面を /interviews 配下に一本化する

## 背景

意見募集の作成・編集画面が2系統あった。

| URL | できたとき | 紐づく施策の編集 | プレビュー |
|---|---|---|---|
| `/bills/[id]/interview/new`, `/bills/[id]/interview/[configId]/edit` | 意見募集が必ず1つの施策に属していたころ（#285） | できない（開いた施策との紐づけを保つ） | できる |
| `/interviews/new`, `/interviews/[configId]/edit` | 施策と多対多にし、抽象テーマ型を足したとき（[抽象テーマ型の作成編集UIと公開導線](20260831_1200_抽象テーマ型の作成編集UIと公開導線.md)） | できる | できない |

同じ意見募集でも開いた入口によって「紐づく施策」の欄が出たり出なかったりして、職員が混乱する。

## 変更

- 作成・編集は `/interviews/new` と `/interviews/[configId]/edit` の1つにする
- 施策ページ配下の作成・編集ページは削除し、`next.config.ts` の `redirects` で転送する
  - `/bills/:id/interview/new` → `/interviews/new?policyId=:id`
  - `/bills/:id/interview/:configId/edit` → `/interviews/:configId/edit`
- `/interviews/new?policyId=` で来たときは、その施策にチェックを入れた状態で始める。戻るリンクは施策のインタビュー設定一覧へ。存在しない施策IDは無視する
- 施策のインタビュー設定一覧・全体のインタビュー管理一覧・複製・他施策への複製の遷移先を `/interviews/...` にそろえた
- プレビューは施策単位で発行するため、フォームで紐づけている施策の先頭で発行する（紐づく施策が無ければボタンを出さない）。表示されるのは従来どおり、その施策の募集中（なければ最新）の意見募集
- AIで設定を生成
  - 題材の施策は、フォームで紐づけている施策の先頭に一本化した（`billId` を廃止）
  - 開いた時点で施策が紐づいていれば、従来の施策配下と同じく自動で生成を始める

## 変えないもの

- レポート・トピック解析は施策ページ配下（`/bills/[id]/interview/[configId]/reports` など）のまま
- プレビューの仕組み（施策単位のトークン）
