# シャドウトークンと罫線の方針（D-6）

> Epic #8 / Issue #12 ／ 作成日: 2026-08-19

佐賀市要望（D-6）により、背景と文字掲載部分の区切りは**線ではなくシャドウ**で表現する。本ドキュメントは、その方針と「意図的に残す罫線」の判断基準をまとめる。

## シャドウトークン

`packages/branding/src/shadows.ts` で定義し、web / admin 双方から `shadow-card` / `shadow-raised` / `shadow-focus` として使える。

| トークン | 値 | 用途 |
|---|---|---|
| `shadow-card` | `0 1px 2px rgba(43,43,43,0.06), 0 1px 1px rgba(43,43,43,0.04)` | 既定。カード・入力欄など面を背景から浮かせる |
| `shadow-raised` | `0 2px 6px rgba(43,43,43,0.08)` | ダイアログ・ポップオーバー・メニューなど浮遊面 |
| `shadow-focus` | `0 0 0 3px rgba(0,119,200,0.35)` | フォーカスリング（`sky/700` 由来） |

`rgba` の値は `PRIMITIVES` の hex から変換して生成しており、色の二重管理は発生しない。**有彩色のシャドウは使わない**（`shadows.test.ts` が機械的に検証）。

## 罫線を残してよい箇所

要求仕様3.4は「フォーカスリングと入力欄の下線を除き罫線を使わない」としている。ただし、**罫線が意味のある境界を担っている箇所は残す**。シャドウに置換すると情報が失われるためである。

| 分類 | 例 | 判断 |
|---|---|---|
| フォーカスリング | `outline` / `border-ring` | **残す**（仕様が明示） |
| 入力欄の枠・下線 | `input` / `textarea` / `select` の `border-input` | **残す**（仕様が明示。入力可能領域の明示は機能的意味を持つ） |
| 区切り線 | テーブルの行区切り、リストの `border-b`、`separator` | **残す**。データの行境界は意味情報であり、シャドウでは表現できない |
| 状態の表現 | `border-transparent` ↔ 選択時に色付き罫線（タブ・チップ） | **残す**。選択状態を色面だけで示すと、色覚特性による識別困難が生じうる |
| ステッパーの接続線 | `bill-status-progress.tsx` | **残す**。進捗の連続性を示す構造的な線 |
| 吹き出しの形状 | `speech-bubble.tsx` | **残す**。装飾ではなく形状そのもの |
| `border-none` | 明示的な打ち消し | 対象外 |
| **カード・セクションの外周** | `ui/card`、各種パネル | **シャドウに置換する** |

## 全要素のデフォルト境界色（`@layer base` の `* { border-border }`）

**残す**。Tailwind の preflight により `border-width` の既定は `0` なので、この宣言は「罫線を引いたときの既定色」を決めるだけで、罫線そのものを増やさない。撤去すると `border-color` が `currentColor`（＝文字色）にフォールバックし、かえって濃い線になる。

## フォーカスリングの色

`globals.css` の `*:focus-visible` などは `var(--primary)`（`sky/400`、対白 **2.01:1**）を使っていたため、**WCAG 2.1 のUI部品基準3:1を満たしていなかった**。`var(--ring)`（`sky/700`、対白 **4.70:1**）に変更した。

## テーマの差し替え方（他自治体でのフォークを想定）

面の区切りをどう見せるかは **`--shadow-card` 1つで決まる**。`box-shadow` は `0 0 0 1px <色>` と書くと罫線と同じ見た目になるため、この変数だけで「影／罫線／区切りなし」を切り替えられる。

```css
/* 既定（佐賀市）: 影で浮かせる */
--shadow-card: 0 1px 2px rgba(43,43,43,0.06), 0 1px 1px rgba(43,43,43,0.04);

/* 罫線で区切りたい場合 */
--shadow-card: 0 0 0 1px var(--border);

/* 区切りを出さない場合 */
--shadow-card: none;
```

`border` と違い `box-shadow` は要素サイズに影響しないので、切り替えてもレイアウトがずれない。

変更手順は2通り。

1. `packages/branding/src/shadows.ts` を編集して `pnpm --filter @mirai-gikai/branding build:css` で再生成する（推奨）
2. 各アプリの `globals.css` で `--shadow-card` を後から上書きする（TSを触らずに済む）

### 呼び出し側では罫線色を直接書かない

`className="border border-black"` のような指定は、テーマを変えても追従せず、`shadow-none` は今回のシャドウを打ち消してしまう（実際に `bill-card.tsx` と `compact-bill-card.tsx` がこの状態だった）。1箇所だけの例外的な調整に限り `className` で上書きしてよいが、色はトークンを使うこと。

なお variant（`elevated` / `flat` 等）は**導入していない**。入れ子カードのように「影を出したくない面」が現時点で存在せず（Card 利用17ファイル中、Dialog との入れ子は0件）、選択肢を増やすと他自治体の理解コストになるため。必要になった時点で追加する。

## 未完了（後続Issueで対応）

本Issueで置換したのは以下。

- 共通UIプリミティブ（card / dialog / popover / dropdown-menu）
- 市民向けの主要カード（議案カード・一覧カード・これから掲載される議案）
- 浮遊面（テキスト選択ツールチップ・スキップ操作ポップオーバー・長押しヒント）
- パネル（時間切れプロンプト・有識者登録バナー）
- 開発用UIプレビューのショーケース枠

**残っているのはボタン・チップの輪郭**（`back-to-bill-button`、`quick-reply-buttons`、`topic-filter-chips` 等）。これらは押せることを示す機能的な境界であり、シャドウに置き換えると押下可能性が伝わりにくくなるため罫線を維持する。ただし `border-gray-800` `border-black` のような**パレット外の色指定が残っている**ので、色のトークン化は **#13（web）/ #14（admin）** で行う。
