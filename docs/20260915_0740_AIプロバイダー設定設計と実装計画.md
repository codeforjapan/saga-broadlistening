# AIプロバイダー設定設計と実装計画

> For agentic workers: subagent-driven-development のタスク単位で実装・検証する。

**Goal:** Issue #42 の共通レジストリを導入し、この案件では Bedrock を使い、横展開先では本番を含めて設定から接続先とモデルを変更できるようにする。

**Architecture:** packages/shared にモデル選択、許可リスト、認証、プロバイダーレジストリを集約する。web/admin/worker は同じ解決処理を経由する。設定は実行環境から読み取り、NODE_ENV や VERCEL_ENV によるプロバイダー固定はしない。

**Tech Stack:** AI SDK 6、amazon-bedrock 4、openai 3、google 3、Vercel AI Gateway、AWS SDK credential chain、Vitest。

**Spec:** 本文の設計を実装仕様とする。2026-09-15 にユーザーが本番も env/config による切り替えを明示したため、Issue 本文の Gateway 撤去・本番のコード固定より本仕様を優先する。

## 制約と設定

- develop 分岐の専用worktreeで作業し、確認済みのベースは a2544c77。変更前の pnpm test は1794件成功。
- AI_ALLOWED_PROVIDERS は bedrock,gateway,openai,google から選ぶ。既定は bedrock。未知・空の設定はエラーとし、通信前に検証する。
- モデルは provider:modelId 形式。例 bedrock:jp.anthropic.claude-sonnet-4-6、gateway:openai/gpt-4o、openai:gpt-4o、google:gemini-2.5-flash。
- 既存の provider/model 形式は明示的な gateway 指定として扱う。別モデルや Bedrock への暗黙変換・フォールバックはしない。保存済み設定は切替前に管理画面で選び直す。
- 優先順位は個別指定（DB/UI/DI）→用途別env→AI_DEFAULT_MODEL→コードのBedrock既定値。既存データを別モデルへ無断で変更しない。
- 用途は default, chat, interview, summary, moderation, contentRichness, configGeneration, simulation, topicAnalysis, topicWriting, opinionBackfill, opinionTags。env は AI_CHAT_MODEL、AI_CONTENT_RICHNESS_MODEL 等のスネーク大文字。
- この案件のデフォルトは Sonnet 4.6、インタビューとトピック解析・タグ付けは Haiku 4.5。AI_DEFAULT_MODEL 指定時は全用途の未指定値をそれで上書きする。
- AWS_REGION は ap-northeast-1 が既定。AWS_PROFILE によるローカルSSO、ECS Task Role、Vercel OIDC（audience sts.amazonaws.com）を共通実装で扱う。
- 選択しないプロバイダーのキーは不要。選択時にキー未設定を識別できるエラーにする。
- Guardrail 設定を Bedrock の providerOptions に渡す共通口を設ける。その他プロバイダーには付けない。
- web_search は対応する OpenAI の経路でのみ送信する。その他のアプリ用ツールは維持する。
- 既存の DI を維持し、Fake model に認証やenvを要求しない。プロバイダーを含む実際のモデルIDを利用ログに記録する。
- モデルカタログ全面刷新は #43。今回は Bedrock の最低限の選択肢と既存料金計算の経路識別対応を含め、未知の料金を別モデルで代用しない。
- クラウド設定・キー失効・本番デプロイは行わず、コードと設定例をPRにする。

## 運用例

### この案件（Bedrock）

```dotenv
AI_ALLOWED_PROVIDERS=bedrock
AWS_REGION=ap-northeast-1
# ローカルのみ。実際に利用権限のある自分のプロファイル名を使う。
AWS_PROFILE=saga-koucho-dev
```

AI_DEFAULT_MODEL を省略すると、インタビュー・トピック分析・意見タグは Haiku 4.5、それ以外は Sonnet 4.6。全体を同じモデルに揃える場合は以下を加える。

```dotenv
AI_DEFAULT_MODEL=bedrock:jp.anthropic.claude-sonnet-4-6
# 必要な用途だけ変更する場合
AI_TOPIC_ANALYSIS_MODEL=bedrock:jp.anthropic.claude-haiku-4-5-20251001-v1:0
```

モデル指定を追加・変更したらプロセスを再起動する。Vercelでは環境変数変更後の再デプロイが必要。AWS_REGION は Vercel 自動設定値に任せずプロジェクト側で明示する（[公式説明](https://vercel.com/docs/oidc/aws)）。Vercel では AWS_PROFILE を設定せず AWS_ROLE_ARN を指定し、既存の audience `sts.amazonaws.com` のロールを使う。AWS Batch は Task Role を使用する。

### 横展開先（Gateway、または直接接続）

```dotenv
AI_ALLOWED_PROVIDERS=gateway
AI_DEFAULT_MODEL=gateway:openai/gpt-4o
AI_GATEWAY_API_KEY=your-key
```

```dotenv
AI_ALLOWED_PROVIDERS=openai,google
AI_DEFAULT_MODEL=openai:gpt-4o
AI_TOPIC_ANALYSIS_MODEL=google:gemini-2.5-flash
OPENAI_API_KEY=your-key
GOOGLE_GENERATIVE_AI_API_KEY=your-key
# 形式例。運用時点の契約・公式料金に合わせる。
AI_MODEL_PRICING='{"openai:gpt-4o":{"inputTokensPerMillionUsd":2.5,"outputTokensPerMillionUsd":10}}'
```

アプリの本番モードでも同じルールが適用される。許可リストとキーは独立しており、キーがあっても許可リスト外には送信しない。設定を空文字で定義すると誤設定としてエラーになるため、未使用の AI_*_MODEL は行ごと省略する。モデル自身が対象プロバイダー・リージョンに存在し、必要な推論機能に対応している必要がある。

この案件のAWS CDK worker設定は `topic-analysis-stack.ts` のコンテナ環境変数に bedrock を指定している。横展開先で別プロバイダーを使用する場合はコンテナの環境変数と選択プロバイダーのSecret注入をその環境のデプロイ設定で変更する。Cloud Runのprovisionスクリプトは許可したプロバイダーのAPIキーだけをSecret対象に追加する。Cloud RunでBedrockを使う場合は、別途AWS credential chainで解決できる認証を用意する。

### 利用料金と上限

`AI_MODEL_PRICING` は `provider:modelId` ごとの入力・出力単価（USD/100万トークン）を指定するJSON。共通単価表より優先する。直接接続や独自モデルなど単価表にない経路では、webのチャット・インタビューは推論前にエラーとし、未知の単価を0ドルとして上限判定を通過させない。実際の契約に応じた単価を設定する。管理画面の概算表示は組み込み単価表を使う。キャッシュやGuardrail等の追加料金を含めた請求額との完全一致は対象外。

### 既存の保存済み設定

`openai/gpt-4o` や `anthropic/claude-haiku-4.5` といった旧IDは Gateway の明示的指定として解釈する。Bedrockへの読み替えはしない。Bedrock のみ許可する切替前に、管理画面のAIモデルを「環境の既定モデル」または Bedrock のモデルへ変更する。

DBの `chat_model` は NOT NULL のため、環境の既定モデルは空文字で保存する。読込時は未指定として扱い、envの変更に追従する。新しいseedにも空文字を使い、実行時のモデルを固定しない。

### DBを変更しない疎通確認

```bash
aws sso login --profile saga-koucho-dev
AWS_PROFILE=saga-koucho-dev AWS_REGION=ap-northeast-1 \
  pnpm --filter @mirai-gikai/topic-analysis-worker ai:smoke
```

.envを読み込む場合はルートで以下を実行する。短文1回、最大256出力トークンで、モデルID・応答・使用トークンを出力する。

```bash
pnpm exec dotenv -e .env -- pnpm --filter @mirai-gikai/topic-analysis-worker ai:smoke
```

`pnpm check:ai-models` は Gateway のカタログ確認専用であり、Bedrock等の実在確認には上のsmokeコマンドを使う。未知モデルの単価やキャッシュ・Guardrail等の追加料金は別途確認する。モデルカタログ・料金管理の全面的な再定義は #43 で扱う。
