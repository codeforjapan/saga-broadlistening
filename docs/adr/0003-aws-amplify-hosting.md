# ADR 0003: フロントエンドホスティングにAWS Amplifyを採用（Vercelではなく）

## ステータス

提案中

## 日付

2026-07-14

## コンテキスト

バックエンドは AWS ECS Fargate + Bedrock で構成されすでに AWS 内に閉じている。フロントエンド（Next.js）のホスティングについて、ベースにしている mirai-gikai は Vercel を前提としているが、単一ベンダーへの統合とコスト整合性の観点から AWS Amplify が検討された。

## 決定

フロントエンドホスティングに AWS Amplify Hosting を採用する（Vercel は採用しない）。

## 根拠

- 技術的考慮: 全体が AWS 内に閉じ、IAM/VPC などの統合が容易になる。
- コスト: PJ-1746 の経費見積りは AWS 従量課金（約25万円/月目安）のみを想定しており、Vercel 分の別枠は計上されていない。
- 調達面: 自治体向け契約では単一ベンダーの方が費用の説明・請求が単純。

## 影響

### メリット

- 単一ベンダーに統合できる
- コスト見積りと整合する
- AWS内でのネットワーク・権限管理が容易

### 懸念点

- Next.jsのISR/Edge Functions関連の開発体験がVercelネイティブより劣る
  - 緩和策: Amplify HostingのSSR対応機能を早期に検証（PoC）し、必要な機能が問題なく使えるか確認する。

## 代替案

Vercel。Next.js の DX が最も良いメリットがあるが、別ベンダーのコスト・契約が必要になり、AWS リソースとの統合も複雑になるため不採用。

## 今後の方向性

PoCでAmplify HostingのSSR機能に問題が見つかった場合、本ADRを見直す。
