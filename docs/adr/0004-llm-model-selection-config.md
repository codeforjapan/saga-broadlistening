# ADR 0004: LLMモデル選定を設定で切り替え可能にする

## ステータス

提案中

## 日付

2026-07-14

## コンテキスト

LLM（バックエンドは AWS Bedrock 経由で呼び出す）は今後新しいモデルが継続的に登場し、また用途（要約、対話、政策文書生成など）によって適したモデルが異なる可能性がある。単一モデルをコードにハードコードすると、モデルの追加・入れ替えのたびにコード変更・再デプロイが必要になる。

## 決定

LLMモデルをコードにハードコードせず、ユースケースごとに設定（モデルID）で切り替え可能な構成にする。

## 根拠

- 技術的考慮: Bedrock はリクエストごとにモデル ID を指定できるため、設定切り替えのみで対応可能。
- 将来の柔軟性: 新モデル登場時に再デプロイ不要。
- ユースケースごとの最適化: 要約用・対話用など用途ごとに異なるモデルを使い分けられる。

## 影響

### メリット

- 新モデルへの追従が容易
- ユースケースごとに最適なモデルを選べる
- コード変更なしで切替可能

### 懸念点

- 設定管理の複雑化（ユースケース×モデルのマッピングが増えると管理コストが上がる）
  - 緩和策: 設定はDBまたは環境変数で一元管理し、変更履歴を追えるようにする。モデル追加時の検証（回帰テスト等）プロセスを整備する。

## 代替案

単一モデルをコードにハードコードする。実装がシンプルというメリットがあるが、モデル追従性が低くユースケースごとの最適化ができないため不採用。

## 今後の方向性

ユースケース→モデルIDのマッピングの実装方式（env変数か設定DBか）を次のタスクとして具体化する。
