# ADR 0001: Supabase Cloudの採用（セルフホストではなくマネージドサービスを使用）

## ステータス

提案中

## 日付

2026-07-14

## コンテキスト

佐賀市AI公聴基盤（saga-broadlistening）は team-mirai/mirai-gikai OSS をベースに構築する。データベースは mirai-gikai が採用している Supabase を引き続き利用する方針だが、AWS ECS Fargate 上へのセルフホストか、Supabase Cloud（マネージドサービス）利用かが、2026-06-02 時点の Notion 整理資料「佐賀市AI公聴基盤 提案書内部整理資料」で未確定事項として残っていた。懸念点として Supabase のデータ主権（ISMAP など政府調達要件への適合）が挙げられていた。

## 決定

Supabase Cloud（Tokyo リージョン）を採用する。セルフホストは行わない。

## 根拠

- 技術的考慮: セルフホストは DB の運用・バックアップ・スケーリングを CfJ 側で担う必要があり運用負荷が高い。
- コスト: PJ-1746 のサーバー費見積り（AWS 従量課金 約25万円/月）はセルフホスト DB の運用コストを想定していない。
- 時間的制約: mirai-gikai が Supabase Cloud 想定で作られているため、そのまま使う方が開発速度が上がる。

## 影響

### メリット

- 運用負荷が低い
- mirai-gikai との互換性が高い
- 迅速な開発着手が可能

### 懸念点

- データ主権/ISMAP適合の懸念
  - 緩和策: Tokyo リージョンを明示指定し、ISMAP 適合が必須と判明した場合は ECS セルフホストへの切替を検討する。

## 代替案

AWS ECS 上へのセルフホスト（Postgres on ECS/RDS）。データを完全に AWS 管理下に置けるメリットがあるが、運用負荷・コスト増、開発速度低下のため不採用。

## 今後の方向性

佐賀市側で ISMAP 適合が要件として明示された場合、本 ADR を見直しセルフホストへの移行を検討する。
