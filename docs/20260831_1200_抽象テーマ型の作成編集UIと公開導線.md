# 抽象テーマ型（施策に紐づかない意見募集）の作成UI・編集UI・公開導線

## 背景

Epic #54 の再定義で `interview_configs` は「意見募集（テーマ）」の独立した単位になり、
施策とは `policies_interview_configs` による多対多になった。施策0件のテーマ
（＝抽象テーマ型）はスキーマ上許容されているが、次が未実装だった。

- 管理画面に作成UIがない（`createInterviewConfig(billId, input)` が施策IDを必須にしている）
- 編集ルートが `/bills/[id]/interview/[configId]/edit` しかなく、施策なしでは開けない
- 公開側の参加導線が `/bills/[id]/interview` 起点で、テーマ単独のURLが存在しない
- テーマ一覧ローダーが `policies_interview_configs` を起点に引くため、施策0件のテーマは出ない

## 方針

### 1. テーマ単独の参加URLを新設する

| URL | 内容 |
| --- | --- |
| `/interviews/[slug]` | テーマのLP |
| `/interviews/[slug]/disclosure` | 情報開示 |
| `/interviews/[slug]/chat` | 対話画面 |

`interview_configs.slug` は NOT NULL / UNIQUE で「公開ページのURLに使う識別子」と
定義済みなので、これをそのまま使う。

### 2. 参加導線を `InterviewTarget` で抽象化する

```ts
export type InterviewTarget =
  | { kind: "policy"; policyId: string; previewToken?: string }
  | { kind: "theme"; slug: string };
```

LP・情報開示・チャットのリンク生成をすべてこの型経由にし、
施策経由（従来）とテーマ単独を同じコンポーネントで扱う。

### 3. チャットAPIを config 起点にする

`POST /api/interview/chat` のリクエストから `billId` を外し、`interviewConfigId` を受ける。
サーバ側で config → 紐づく施策 → 施策情報、の順に解決する。

- クライアントが施策IDを指定できなくなるため、「テーマAのconfigと無関係な施策Bの
  コンテキスト」を組み合わせる余地がなくなる
- プレビュートークンの検証は「config から解決した施策ID」に対して行う

### 4. テーマカードの遷移先を統一する

テーマ単独URLができたことで、施策経由でしか辿れないテーマを一覧から落とす
`buildInterviewThemes` の絞り込み（1施策1テーマ）が不要になる。
カードは常に `/interviews/[slug]` を指す。

一覧に出す条件は次のとおり。

- テーマが募集中（`status = 'open'`）である
- かつ「施策の紐付けが0件」または「公開済み施策が1件以上紐づく」

### 5. 意見（レポート）表示を施策なしに対応させる

抽象テーマの対話も意見として提出・公開されるため、次を施策なしで動くようにする。

- `/report/[id]/complete`（提出直後）
- `/report/[id]`（公開意見）

施策名・施策詳細リンクの箇所は、施策があればこれまで通り、なければテーマ名と
テーマLPへのリンクにフォールバックする。

### 6. 管理画面

| URL | 内容 |
| --- | --- |
| `/interviews/new` | 意見募集の新規作成（施策の紐付けは任意・複数選択） |
| `/interviews/[configId]/edit` | 意見募集の編集（施策の紐付けを含む） |

`interviewConfigSchema` に `policy_ids`（任意）と `thumbnail_url` を追加し、
`createInterviewConfig` / `updateInterviewConfig` が紐付けを同期する。
既存の `/bills/[id]/interview/...` 配下の導線は施策IDを `policy_ids` として渡すだけで、
これまでと同じ動作を維持する。

抽象テーマにはフォールバック元の施策サムネイルがないため、
テーマ自身の `thumbnail_url` をアップロードできるようにする。

## 対象外（今回やらないこと）

- シミュレーション機能（`interview-simulation`）は施策のナレッジと完了レポートを前提と
  しているため、施策が紐づかないテーマではタブごと出さない
- プレビュートークンは `preview_tokens.policy_id` が NOT NULL のため施策専用のまま。
  抽象テーマのプレビューは対象外（下書き状態では公開側から参照できない）
