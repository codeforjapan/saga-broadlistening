# develop環境（staging）全サービス環境変数・シークレット設定チェックリスト

`web` / `admin` / GitHub Actions / AWS Secrets Managerにまたがる、develop環境（staging）を
本番相当に動かすために必要な環境変数・シークレットの全体像。

> **前提の断り書き**: このドキュメントは実際にVercelダッシュボードの`c4j`チームの設定を
> 見て書いたものではない（このセッションのVercel CLIアカウントは`c4j`チームへのアクセス権が
> ないため確認できなかった）。各アプリのソースコード（`process.env.*`参照箇所）と
> `.env.example` / 既存docsを突き合わせて洗い出した一覧であり、**prdで実際に設定した内容と
> 完全に一致する保証はない**。prdの設定値を横に並べながら本チェックリストで漏れがないか
> 確認する使い方を推奨する。

## 全体像：4つの設定先

| # | 設定先 | 対象 | 用途 |
|---|---|---|---|
| ① | GitHub `staging` Environment Secrets | CI/CD | `develop`へのpush時にSupabase migrate・CDK deploy・worker ECR pushを実行 |
| ② | Vercelダッシュボード（`saga-kocho-web`のPreview環境） | webアプリ実行時 | Supabase接続・OGP等のURL生成・AIチャット等 |
| ③ | Vercelダッシュボード（`saga-kocho-admin`のPreview環境） | adminアプリ実行時 | Supabase接続・Bedrock呼び出し・AWS Batch起動・Google OAuth連携 |
| ④ | AWS Secrets Manager（アカウント`826784631888`） | workerコンテナ実行時 | AWS Batchで動くworkerがSupabase/AI Gatewayに接続する認証情報 |

①は`docs/20260831_1030_deploy用GitHubシークレット設定手順.md`で設定済み・稼働確認済み。
④は`docs/20260906_0848_develop環境Vercel環境変数とSecrets実値設定手順.md`に詳細手順あり。
本ドキュメントは②③（Vercel環境変数）を中心に、全体像を1枚にまとめる。

## Supabase側の前提

develop環境は`docs/20260730_1736_deploy_yml_secrets_guide.md`で構築した通り、Supabase
Branchingの`develop`ブランチ（親プロジェクト配下）を使う。②③で設定する
`NEXT_PUBLIC_SUPABASE_URL` / `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` / `SUPABASE_SECRET_KEY`は
**GitHub Secretsの`SUPABASE_PROJECT_REF`/`SUPABASE_DB_PASSWORD`とは別物**（CI用の接続情報 vs
アプリ実行時の接続情報）。Supabase Dashboardで`develop`ブランチのプロジェクトを開き、
**Settings > API** から取得する。

## ② Vercel `saga-kocho-web` のPreview環境変数

`web/src/lib/env.ts`・`packages/supabase/src`の参照箇所から洗い出し。

### 必須（未設定だとビルド/実行時エラー）

| 変数名 | 用途 | 取得元 |
|---|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | Supabase接続（クライアント） | Supabase Dashboard（developブランチ） > Settings > API |
| `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | 同上 | 同上 |
| `SUPABASE_URL` | Supabase接続（サーバー、Admin Client） | 同上（`NEXT_PUBLIC_SUPABASE_URL`と同じ値） |
| `SUPABASE_SECRET_KEY` | 同上（Service Role Key） | 同上 |

### 推奨（無くても動くが、本番相当のリンク遷移・OGPには必要）

| 変数名 | 用途 | 値の目安 |
|---|---|---|
| `ADMIN_URL` | adminへのリンク遷移（プレビュー画面の「戻る」等） | developのadmin Preview URL（下記「PreviewのURLについて」参照） |
| `NEXT_PUBLIC_WEB_URL` | OGP画像URL・`metadataBase`生成 | developのweb Preview URL |
| `REVALIDATE_SECRET` | オンデマンド再検証用シークレット | ランダムな文字列（prdと同じ値を使い回してよい） |

### 任意（機能フラグ・分析系、未設定でも安全にデフォルト動作）

| 変数名 | 用途 |
|---|---|
| `LANGFUSE_PUBLIC_KEY` / `LANGFUSE_SECRET_KEY` / `LANGFUSE_BASE_URL` / `LANGFUSE_PROMPT_LABEL` | AIチャットのプロンプト管理・監視（Langfuse） |
| `CHAT_DAILY_USER_COST_LIMIT_USD` / `CHAT_DAILY_TOTAL_COST_LIMIT_USD` / `CHAT_MONTHLY_TOTAL_COST_LIMIT_USD` | AIチャットのコストリミット（デフォルト値あり） |
| `NEXT_PUBLIC_GA_TRACKING_ID` | Google Analytics（developでは未設定のままでよいことが多い） |
| `OPEN_DATA_RATE_LIMIT_PER_IP` / `OPEN_DATA_RATE_LIMIT_GLOBAL` | オープンデータAPIのレート制限（デフォルト30等あり） |
| `BASIC_AUTH_USER` / `BASIC_AUTH_PASSWORD` | Basic認証で外部公開を防ぐ場合のみ設定（develop環境は検索エンジンにインデックスさせたくない場合に設定推奨） |

## ③ Vercel `saga-kocho-admin` のPreview環境変数

`admin/src/lib/env.ts`の参照箇所から洗い出し。

### 必須

| 変数名 | 用途 | 取得元 |
|---|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | Supabase接続（クライアント） | Supabase Dashboard（developブランチ） |
| `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | 同上 | 同上 |
| `SUPABASE_URL` | Supabase接続（サーバー、Admin Client） | 同上 |
| `SUPABASE_SECRET_KEY` | 同上（Service Role Key） | 同上 |

### 必須（AWS Batch/Bedrock機能を使う場合。詳細は別ドキュメント参照）

`docs/20260906_0848_develop環境Vercel環境変数とSecrets実値設定手順.md`の「2. Vercel環境変数の設定」を参照。

| 変数名 | 取得元 |
|---|---|
| `AWS_ROLE_ARN` | `MiraiGikaiVercelOidcStack-dev`の出力`VercelBedrockAccessRoleArn` |
| `AWS_REGION` | `ap-northeast-1` |
| `TOPIC_ANALYSIS_BATCH_JOB_QUEUE_ARN` | `MiraiGikaiTopicAnalysisStack-dev`の出力`JobQueueArnOutput` |
| `TOPIC_ANALYSIS_BATCH_JOB_DEFINITION_ARN` | `MiraiGikaiTopicAnalysisStack-dev`の出力`JobDefinitionArnOutput` |

> **セキュリティ注意**: 上記AWS系変数はVercelの`Preview`環境変数がブランチを絞らない限り
> 任意のfeatureブランチのプレビューにも適用される。可能なら`develop`ブランチに限定すること
> （別ドキュメントに詳細あり）。

### 推奨

| 変数名 | 用途 | 値の目安 |
|---|---|---|
| `NEXT_PUBLIC_WEB_URL` | webへのリンク | developのweb Preview URL |
| `REVALIDATE_SECRET` | webと同じ値 | prdと同じ値を使い回してよい |
| `ADMIN_MCP_TOKEN` | `/api/mcp`のBearer認証トークン | ランダムな文字列 |

### 任意

| 変数名 | 用途 |
|---|---|
| `LANGFUSE_PUBLIC_KEY` / `LANGFUSE_SECRET_KEY` / `LANGFUSE_BASE_URL` | Langfuse（webと共通） |
| `API_TEST_SECRET_TOKEN` | `/api/tests/*`（`docs/20260826_2310_api-test-endpoints-usage.md`参照）を使う場合のみ。ランダムな文字列を生成して設定 |
| `GCP_PROJECT_ID` / `GCP_REGION` / `GCP_TOPIC_ANALYSIS_JOB` / `GCP_SA_KEY` | **旧GCP Cloud Run Job起動用（`admin/src/lib/cloud-run-job.ts`）。実際に呼び出しているコードは見当たらず、AWS Batchへの移行（#48/#66/#49）で使われなくなっている可能性が高い。develop環境では設定不要と考えられる** |

## Previewの実URLについて

`ADMIN_URL` / `NEXT_PUBLIC_WEB_URL`にはdevelopブランチの実デプロイURLを設定する必要がある。
Vercelは同一Gitブランチのデプロイに対して固定のBranch URL（`https://<project>-git-<branch>-<team>.vercel.app`
形式）を割り当てる。正確な形式はプロジェクトごとに異なる場合があるため、Vercel Dashboardの
**Deployments**タブでdevelopブランチの最新デプロイを開き、URLをコピーして使うこと。

## 動作確認チェックリスト

1. `develop`へpush → `Migrate DB then Deploy`が成功し、Vercelデプロイが起動することを確認
2. webのdevelop Preview URLにアクセスし、Supabaseからデータが表示されることを確認
3. adminのdevelop Preview URLにログインし、Google OAuthでログインできることを確認
   （GitHub Secretsの`SUPABASE_AUTH_EXTERNAL_GOOGLE_CLIENT_ID`等が正しく`config.toml`に反映されている前提）
4. web→adminへのリンク遷移（プレビュー画面の「戻る」等）が正しいURLに飛ぶことを確認
5. AWS Batch/Bedrock機能を使う場合は`docs/20260906_0848_...`の動作確認手順を実施
