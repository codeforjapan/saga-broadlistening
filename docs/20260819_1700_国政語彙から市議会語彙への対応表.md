# 国政語彙から市議会語彙への対応表（#20）

> Epic #8 / Issue #20 ／ 作成日: 2026-08-19 ／ **佐賀市の確認待ち**

みらい議会（国政向け）由来の語彙を、佐賀市の広聴基盤の語彙へ再定義した。本ドキュメントは適用した対応表と、判断が必要な項目をまとめる。

## 対応表

置換は複合語から先に適用している（順序が重要）。

| 変更前 | 変更後 | 備考 |
|---|---|---|
| 法案 | 議案 | 市議会の標準語彙 |
| 法案提出前 | 議案提出前 | |
| 法案成立 | 議案可決 | 市議会では「可決」 |
| 注目法案 | 注目の議案 | |
| 成立法案 | 可決された議案 | |
| 国会 | 市議会 | |
| 国会会期 | 議会会期 | |
| 国会閉会中 / 国会会期中 | 閉会中 / 会期中 | |
| 国会名 | 会期名 | admin の入力フォーム |

## 一院制への再定義

市議会は一院制のため、二院制前提の表示を組み替えた。**DBの enum 値は変更していない**（変更にはマイグレーションが必要）。

### 審議ステータス（`bill_status_enum`）

| enum値 | 変更前の表示 | 変更後の表示 |
|---|---|---|
| `preparing` | 準備中 | 準備中 |
| `introduced` | 提出済み | 提出済み |
| `in_originating_house` | 衆議院審議中 / 参議院審議中（発議院で分岐） | **委員会審査中** |
| `in_receiving_house` | 参議院審議中 / 衆議院審議中（同上） | **本会議審議中** |
| `enacted` | 成立 | **可決** |
| `rejected` | 否決 | 否決 |

発議院による分岐が不要になったため、`getBillStatusLabel()` から第2引数 `originatingHouse` を削除した。

### 進捗ステッパー（`bill-status-progress.tsx`）

```
変更前: 法案提出 → 衆議院審議 → 参議院審議 → 法案成立
変更後: 議案提出 → 委員会審査 → 本会議審議 → 議案可決
```

発議院に応じてステップ順を入れ替える `getOrderedSteps()` は一院制では意味がないため削除した（テストも削除）。

### 提出元区分（`house_enum`）

`HR` / `HC` は国会の衆議院・参議院を表す値だったが、市議会の提出区分として読み替えた。

| enum値 | 変更前 | 変更後（暫定） |
|---|---|---|
| `HR` | 衆議院 | **市長提出** |
| `HC` | 参議院 | **議員提出** |

> ⚠️ **これは暫定の再定義で、佐賀市の確認が必要**。市議会の議案は「市長提出議案」と「議員提出議案」に分かれるため妥当性はあるが、enum値の名前（`HR` = House of Representatives）と意味が乖離する。enum そのものを再定義する場合はマイグレーションを伴うため、フォローアップIssueで扱う。

## 対象外（フォローアップIssue）

Issue #20 のスコープ定義どおり、以下は変更していない。

- DBのテーブル名・カラム名（`bills`, `diet_sessions`, `shugiin_url`, `house_enum`, `bill_status_enum`）
- URLパス（`/bills/[id]`, `/kokkai/[slug]/bills`）とディレクトリ名（`features/diet-sessions/` 等）
- ワークスペースのパッケージ名（`@mirai-gikai/*`）
- 内部識別子（`supabase/config.toml` の `project_id`、`MCP_CLIENT_ID`）

## 佐賀市に確認したい項目

1. **「議案」で統一してよいか**（条例・予算・人事案件などを包括する語として）
2. **審議段階の実際のフロー** — 「委員会審査 → 本会議」で合っているか。委員会付託されない議案の扱い
3. **提出元区分** — 「市長提出 / 議員提出」で合っているか
4. **議決結果の語彙** — 「可決 / 否決」以外に「同意 / 承認 / 認定」等の区分が必要か
