# develop環境（staging）のAWSアカウント方針決定

[develop環境（staging）整備計画](20260831_1206_staging環境整備計画.md)の「手順1: AWSアカウントを用意する」
「手順4: CDK Deploy/Diffワークフローをstg対応にする」に対する決定事項と、実施した変更のまとめ。

## 決定事項

### 1. stg用に新規AWSアカウントは作らず、dev環境（`826784631888` / `saga-koucho-dev`）を流用する

develop環境専用の独立したAWSアカウントは作らず、既存のdev環境（AWSアカウント
`826784631888`、プロファイル名`saga-koucho-dev`）をそのまま使う。

### 2. CDK側の環境命名は「stg」を廃止し、「dev」に統一する

- `infra/aws-cdk`の環境命名（`dev` / `stg` / `prd`）は、mirai-gikai本体（フォーク元
  `team-mirai/mirai-gikai`）の慣習ではなく、このフォークでAWS/Bedrock基盤を追加した際
  （2026-08-09, `e46df926` / `12d311e7`）に独自に決めたものだった（本体のGitHub Environmentsを
  確認したところ`production` / `staging`のみで、`prd` / `stg`という短縮名は存在しない）。
- 上記の経緯を踏まえた上で、今回は「production/staging」への全面リネームは行わず、
  **`prd` / `dev`の短縮表記のまま維持する**方針とした（既にAWS上にデプロイ済みのprdスタック名
  `MiraiGikaiXxxStack-prd`等を変更しないため、変更範囲を小さく保てる）。
- そのため`stg`という環境区分自体を削除し、`dev` / `prd`の2環境体制にした。
  GitHub Environment名（`production` / `staging`）とCDKのcontext env名（`prd` / `dev`）は
  今後も一致しない点に注意（既存のSupabase/Vercel向けdeploy.ymlと同じ非対称性）。

## 実施した変更

- `infra/aws-cdk/lib/config/types.ts`: `EnvName`から`"stg"`を削除
- `infra/aws-cdk/lib/config/environments/stg.ts`: 削除
- `infra/aws-cdk/lib/config/environments/index.ts`: `stg`registrationと
  `UNCONFIGURED_ACCOUNT_ID`ガード（dev/prdのみになり不要になったため）を削除
- `infra/aws-cdk/lib/stacks/github-oidc-stack.ts`: OIDCロールの信頼条件（trust policy）を
  環境ごとにパラメータ化。`dev`環境は`develop`ブランチ / `staging` Environmentを、
  `prd`環境は`main`ブランチ / `production` Environmentを信頼するようにした
  （従来は全環境で`main` / `production`固定だったため、dev環境のロールは`develop`から
  Assumeできなかった）。信頼するブランチ/GitHub Environment名は、既存の`account`や
  `bedrockModelId`と同様に`EnvConfig`の`trustedBranch` / `trustedGithubEnvironment`
  フィールドとして`lib/config/environments/{dev,prd}.ts`に定義し、スタック側はそれを
  参照するだけにした（スタック内に別のマッピング表を持たせると、環境追加時に2箇所を
  同期する必要が生じるため、既存の「1環境1ファイル」の設定パターンに揃えた）
- `.github/workflows/cdk_deploy_dev.yml` / `cdk_diff_dev.yml`: 新規追加。
  `cdk_deploy.yml` / `cdk_diff.yml`（main・prd向け）と同じ構成で、`develop`ブランチ・
  `staging` GitHub Environment・`context_env=dev`向けに用意した。
  `AWS_CDK_DEV_DEPLOY_ROLE_ARN` Secretが未設定の間はgreen skipになる。
- `infra/aws-cdk/README.md`: 上記に合わせて更新
- `package.json`（`infra/aws-cdk`）: `synth:stg` / `diff:stg` / `deploy:stg`スクリプトを削除

## 未実施（次のアクション）

[develop環境整備計画](20260831_1206_staging環境整備計画.md)の手順2・3が引き続き必要:

1. `AWS_PROFILE=saga-koucho-dev npx cdk deploy MiraiGikaiGitHubOidcStack-dev --context env=dev`
   を手動実行し、更新後の信頼条件（`develop`ブランチ許可）をIAM Roleに反映する
   （既にdev環境にこのスタックがデプロイ済みの場合は差分更新、未デプロイの場合は
   `cdk bootstrap`から必要）
2. デプロイされたRole ARN（`arn:aws:iam::826784631888:role/MiraiGikaiGitHubActionsDeployRole-dev`）を
   GitHubの`staging` EnvironmentのSecretに`AWS_CDK_DEV_DEPLOY_ROLE_ARN`として登録する
3. `develop`へpushして`CDK Deploy [dev]`ワークフローが成功することを確認する

worker（ECR push）・Vercel環境変数・EventBridge Schedulerの扱い（整備計画の手順5〜7）は
本ドキュメントの対応範囲外で、別途対応する。
