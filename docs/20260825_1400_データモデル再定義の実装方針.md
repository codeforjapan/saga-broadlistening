# データモデル再定義（Epic #54）バックエンド実装方針

対象 Issue: #55 / #56 / #57 / #58（#59 の旧スキーマ削除と #62 のシード刷新は後続）

## この PR のスコープ

- `supabase/migrations` の 4 本と `packages/supabase/types/supabase.types.ts` の再生成
- web / admin / packages / worker / tests の **データアクセス層**の追随
- `.tsx` は「型が通る最低限」だけ追随させる（ビルドを常にグリーンに保つため）

## スコープ外（意図的な先送り）

### 1. ディレクトリ名・ファイル名・URL パスの改名はしない

`web/src/features/bills/` → `policies/`、`/bills/[id]` → `/policies/[id]`、
`admin/src/features/bills/` → `policies/` といった改名は **本 PR では行わない**。

理由: 同じファイル群を Epic #8（PR #32）と #20（PR #40）が改修中で、
web/src/features だけで 85 ファイル、admin/src/features で 44 ファイルが競合する。
ディレクトリ改名を重ねると modify/delete コンフリクトになり、デザイン側の作業が
巻き戻るリスクが高い。改名は語彙の再定義（#20）と同じ性質の作業なので、
Epic #8 の完了後にまとめて行う。

そのため本 PR では `bill-repository.ts` が `.from("policies")` を呼ぶ、
`Bill` 型が `Tables<"policies">` を指す、といった名前と実体のズレが残る。
該当ファイルには先送りである旨のコメントを入れる。

### 2. `#59`（旧スキーマ削除）

`bills` / `bill_contents` / `bills_tags` / `chats` と旧 enum は残す。
参照コードが消えたことを確認してから削除する。

### `review_status` を公開状態の正本とする

- 公開されている＝ `review_status = 'published'`。
  RPC・リポジトリの「公開」判定はすべてこれに揃える
- `is_public_by_user` / `is_public_by_admin` は入力条件として残す。
  両方 true になったときに職員レビューを経て `published` へ遷移する
- 職員が非公開にした場合は `hidden`。以後は本人操作による自動公開の対象外
  （旧 `admin_unpublished_at` の役割）

### 施策 ↔ 意見募集の多対多

「この施策の意見募集」は `policies_interview_configs` を経由して引く。

```ts
// 施策に紐づく募集中のテーマ
supabase
  .from("policies_interview_configs")
  .select("interview_configs!inner(*)")
  .eq("policy_id", policyId)
  .eq("interview_configs.status", "open")
```

- 施策 0 件の意見募集＝抽象テーマ型。`interview_configs` に種別カラムは持たない
- 1 施策に複数の意見募集がある場合、既存 UI は **最初の 1 件**を使う
  （複数表示の UI は Epic #8 側で対応する）

### 明示的に Issue から外した判断

| Issue の記述 | 実装 | 理由 |
| --- | --- | --- |
| `chat_usage_events` を廃止 | **残す**。`get_chat_usage_metrics`（分析用 RPC）と admin の MCP ツールのみ削除 | このテーブルと `sum_chat_usage_cost` は分析ではなく、チャット API の実行時ガード（利用者ごとの日次上限・システム全体の日次/月次予算上限）に同期的に使われている。Langfuse は非同期の可観測性基盤で予算判定には使えないため、代替ガードなしに落とすと支出上限が無効化される。代替の設計は #41 / #50 と合わせて別途 |
| `interview_report.is_data_reuse_consented` を廃止 | **残す**（`opinions.is_data_reuse_consented`） | 公開データ API（CC BY 4.0・`/api/open-data/interviews`）の二次利用許諾ゲート。公開同意（`review_status`）とは別の意思表示であり、`published` で代用すると同意していない意見までオープンデータに流れる |
| `interview_report.opinions_reextracted_at` を廃止 | **残す**（`opinions.opinions_reextracted_at`） | 意見再抽出バックフィル（`packages/topic-analysis-core/src/backfill.ts`・admin の実行 UI・worker の `--mode=backfill`）のウォーターマーク。JSONB とは無関係に稼働中 |
| storage ポリシーを `auth.role() = 'authenticated'` で作る | `public.is_admin()` を使う | 既存の `bill-thumbnails` は admin 限定（`20250921000001`）。Issue の DDL どおりだと権限が緩くなる |
| 旧フェーズ連鎖版（`topic` 系）は #51 で削除予定 | 同じ方針で作り直す | #51 が未完のため。`packages/topic-analysis-core` と web/admin が稼働中 |

## 本 PR 後のフォローアップ

- **改名**: `bills` → `policies` のディレクトリ・ファイル・URL パス・型名（Epic #8 完了後）
- **#59**: 旧テーブル（`bills` / `bill_contents` / `bills_tags` / `chats`）と旧 enum
  （`house_enum` / `bill_status_enum` / `bill_publish_status` / `stance_type_enum` /
  `interview_mode_enum` / `interview_report_role_enum`）、旧 storage bucket の一括削除
- **#62**: シードデータの中身を佐賀市の題材へ差し替え
- **AI コストの実行時ガード**: `chat_usage_events` に依存したままなので、Bedrock 移行
  （#41 / #50）に合わせて代替を設計する
- **対話モード**: `interview_configs.mode` は廃止したが、`INTERVIEW_MODES` /
  `bulk-mode` / `targeted-mode` と `InterviewQuestion.target_audience` は
  admin のインタビューシミュレーション機能が独自に使っているため残している。
  DB 由来の概念ではなくなったので、シミュレーション側の整理とあわせて別途削除する
- **#58 の未実装分**: `portal_controls` / `audit_logs` / `guard_events` は
  テーブルを新設しただけで、緊急停止の表示・監査ログの記録・ガードレール検知の
  書き込みはアプリ側未実装。緊急停止 UI と監査ログ閲覧は別 Issue で対応する
  （ガードレール記録は #46 のスコープ）
- **`guard_events` の CHECK 制約**: `product` に応じてセッション参照を必須にしているため、
  セッション作成前（入力ブロック時）のガード発火を記録できない。#46 の実装時に
  制約を緩めるか、セッションを先に作るかを決める
